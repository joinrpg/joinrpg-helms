# Дашборды Coroot как код

`mssql.json` — семь панелей «MSSQL: ВМ и контейнер»: доступная память ВМ,
RSS контейнеров, CPU MSSQL, заполнение файловой системы с данными, дисковый
I/O ВМ, сообщения по уровням и ошибки в логах. Все запросы ограничены одной ВМ.

Идентификатор ВМ передаётся через `--machine-id` и заменяет `__MACHINE_ID__`.
Значение можно получить на ВМ командой `cat /etc/machine-id` или из метки
`machine_id` в Coroot. В публичный JSON реальные идентификаторы не записываем.
Легенды `{{container_id}}` и `{{level}}` интерпретирует Coroot, не Helm.

## Как применяется

Coroot 1.27.4 и coroot-operator 1.10.6 не предоставляют provisioning дашбордов
через наш CR. Скрипт `../scripts/sync-dashboard.py` использует HTTP API,
отдельно от `helm upgrade`. Требуется Python 3.10+ со стандартной библиотекой,
дополнительные пакеты не нужны. Настройки дашбордов сохраняются в служебной БД
сервера Coroot, не в ClickHouse.

Скрипт ищет дашборд по точному имени внутри указанного проекта. Если его нет —
создаёт, если есть — обновляет. При совпадающей конфигурации запись не выполняется.
При нескольких дашбордах с одинаковым именем скрипт останавливается.
Имя служит ключом синхронизации: его изменение в JSON создаёт другой дашборд,
а старый автоматически не удаляется. Не запускайте несколько синхронизаций
одновременно: API не предоставляет атомарное создание по имени.

По умолчанию выполняется только чтение и вывод плана. `--apply` разрешает запись.
Перед обновлением сохраняется уникальная резервная копия в
`docs/coroot-dashboard-backups/` корня репозитория (каталог gitignored).
Если копию сохранить не удалось, обновление не начинается. Для отката можно
передать резервный JSON через `--file`, сохранив прежние параметры проекта.

**Применение заменяет конфигурацию всех панелей этого дашборда**, включая
изменения в UI. При ошибке после создания может остаться пустой дашборд:
повторный запуск найдёт его по имени и продолжит без создания дубликата.
Автоматических повторов POST и удаления дашбордов нет.

## Авторизация и запуск

Нужны права Admin или Editor. Без переменной `COROOT_USER_API_KEY` скрипт
берёт пароль из `COROOT_PASSWORD`, а если он пустой — спрашивает через скрытый ввод.
Cookie хранится только в памяти процесса. Логин берётся из `COROOT_USER`
(по умолчанию `admin`), флаг `--user` имеет приоритет.
Пароль не передаётся аргументом командной строки, скрипт не сохраняет его в файл.
Переменные можно заполнить в локальном gitignored `secrets.env` по шаблону
`secrets.env.example`, затем загрузить в WSL:

```bash
source <(tr -d '\r' < secrets.env)
python3 platform/coroot/scripts/sync-dashboard.py \
  --url "$COROOT_URL" --project "$COROOT_PROJECT_ID" \
  --machine-id "$COROOT_MACHINE_ID"
```

Альтернатива — **пользовательский** Bearer API-ключ в `COROOT_USER_API_KEY`.
Непустой API-ключ имеет приоритет над паролем: для входа по паролю оставьте его пустым.
API-ключ проекта, которым агенты отправляют телеметрию, не подходит.
Не храните учётные данные в JSON или отслеживаемых Git файлах. HTTPS проверяется штатно,
редиректы запрещены. HTTP разрешён только для loopback, например port-forward.
Ответы ограничены 8 MiB, таймаут запроса по умолчанию 30 секунд (`--timeout`).

Из корня репозитория, заменив значения в кавычках (команда подходит для WSL):

```bash
python3 platform/coroot/scripts/sync-dashboard.py \
  --url https://coroot.joinrpg.ru \
  --project 'ID_ПРОЕКТА_ИЗ_URL' \
  --machine-id 'MACHINE_ID_ВМ'
```

`--project` — ID из `/p/<id>/...` в адресной строке, не имя проекта `coroot`.
План не меняет дашборды, но при входе по паролю выполняет POST `/api/login`.
Для применения повторите ту же команду с `--apply`. В PowerShell используйте
`python` и запишите команду одной строкой. Для просмотра готового JSON без сети
можно использовать `--machine-id ... --render`, остальные параметры не нужны.

После применения скрипт перечитывает конфигурацию через GET. Затем откройте
дашборд, проверьте графики за последний час. Сетевые тесты ниже используют
локальный поддельный API, работоспособность панелей на реальном сервере ими
не подтверждается.

```bash
python3 -B -m unittest discover -s platform/coroot/scripts -p 'test_*.py'
```

## Ограничения панелей

- RSS не включает всё потребление cgroup, в частности часть памяти ядра/eBPF.
- Лимит SQL `MSSQL_MEMORY_LIMIT_MB` не равен Docker memory limit.
- Диск показывает всю файловую систему с томом, а не размер файлов SQL.
- Ошибки считаются только по `level=error|fatal`, `unknown` не учитывается.
  Отсутствие данных не означает отсутствие ошибок. `or vector(0)` не используется.
- `increase(...[5m])` показывает скользящий интервал: соседние точки перекрываются.
- Это ресурсный дашборд, не мониторинг блокировок, Query Store или SQL wait statistics.
